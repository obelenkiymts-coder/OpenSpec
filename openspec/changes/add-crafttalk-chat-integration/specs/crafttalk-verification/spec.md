# Spec Delta: crafttalk-verification

## Purpose

Верификация клиента в чате CraftTalk каскадом проверок (ПИНФЛ+телефон → телефон → телефон+год рождения) и выдача боту RAW-массива: данные клиента, действующие займы, сегмент, ссылка на оплату.

## ADDED Requirements

### Requirement: Верификация по ПИНФЛ и телефону
Метод верификации для агента `verification_collector_v1` SHALL первой проверкой искать заёмщика по паре «ПИНФЛ + телефон»: совпадение найдено — верификация пройдена.

#### Scenario: Клиент найден по ПИНФЛ и телефону
- **WHEN** в системе существует заёмщик с указанными ПИНФЛ и телефоном
- **THEN** верификация пройдена и возвращается RAW-массив клиента

### Requirement: Резервная проверка по телефону
Если первая проверка неуспешна, метод SHALL искать телефон как основной активный контакт заёмщика: телефон найден — верификация пройдена.

#### Scenario: Телефон является основным активным контактом
- **WHEN** пара «ПИНФЛ + телефон» не найдена, но телефон числится основным активным контактом заёмщика
- **THEN** верификация пройдена и возвращается RAW-массив клиента

#### Scenario: Телефон не найден ни у одного заёмщика
- **WHEN** телефон не найден как ПИНФЛ+телефон и как основной активный контакт
- **THEN** верификация переходит к проверке «телефон + год рождения»

### Requirement: Резервная проверка по году рождения
Если проверки по ПИНФЛ и телефону неуспешны, метод SHALL принимать проверку «телефон + год рождения» (4 цифры, вводит клиент в чате): совпадение — верификация пройдена.

#### Scenario: Год рождения совпал
- **WHEN** телефон найден у заёмщика и переданный год рождения совпадает с годом рождения заёмщика
- **THEN** верификация пройдена и возвращается RAW-массив клиента

#### Scenario: Год рождения не совпал
- **WHEN** год рождения не совпадает с данными заёмщика, найденного по телефону
- **THEN** верификация считается незавершённой и возвращается ответ с незаполненными параметрами

### Requirement: Незавершённая верификация не является ошибкой
При неуспехе всех проверок метод SHALL возвращать успешный ответ с незаполненными параметрами (данные клиента и займы отсутствуют); CraftTalk ведёт диалог по сценарной заглушке «оператор сейчас недоступен». Ошибки «заёмщик не найден» для этого случая быть не должно.

#### Scenario: Все проверки неуспешны
- **WHEN** ни одна из трёх проверок верификации не пройдена
- **THEN** возвращается ответ с незаполненными параметрами без кода ошибки и без данных клиента

### Requirement: RAW-массив при успешной верификации
При успешной верификации метод SHALL возвращать RAW-массив: данные клиента, все действующие займы (включая просроченные), номер сегмента и ссылку на оплату в МП. Точный состав полей RAW — версия V2 по согласованию с аналитиком и контрактом вендора.

#### Scenario: Клиент с действующими займами
- **WHEN** верифицированный клиент имеет действующие займы
- **THEN** RAW-массив содержит данные клиента, каждый действующий займ, номер сегмента и ссылку на оплату

#### Scenario: Клиент без действующих займов
- **WHEN** верификация пройдена, но действующих займов нет
- **THEN** RAW-массив содержит данные клиента с пустым массивом займов
