# Proposal: Интеграция чата CraftTalk в контур УЗБ МФО (АРМ Коллектор)

Источник: эпик QPAY-39989 (Business Analysis), итоги встречи «Расскажем о CraftTalk» 02.10.2026.

## Why

В узбекском МФО взыскание ведётся только звонками (Genesys) и рассылками — канала чата с просрочником нет. В российском контуре тот же сценарный бот CraftTalk закрывает ~90% трафика диалогов с должниками при 97% успешных верификаций. Внедрение CraftTalk в УЗБ добавляет круглосуточный автоматический канал контакта, повышает собираемость (обещания оплаты конвертируются в платежи) и снимает нагрузку с операторов СВЗ.

## What Changes

Со стороны разработки — только АРМ Коллектор (`uzb-loans-debt-data-collection-service` + UI ARM-collection). CraftTalk и CFS разворачиваются DevOps в нашем k8s, вендор в рантайме не участвует.

- Группа методов API под префиксом `/api/craftalk/...` для трёх JS-агентов CraftTalk MVP: верификация, обещание оплаты, регистрация контакта. Точные имена путей и состав параметров — по контракту вендора (TODO).
- Авторизация CraftTalk как отдельного пользователя-бота (секрет на стороне АРМ, без доступа к UI, аналог роли CHATBOT в РФ); все методы агентов идемпотентны.
- Верификация waterfall: ПИНФЛ+телефон → телефон → телефон+год рождения; при успехе — RAW-массив (данные клиента + действующие займы + сегмент + ссылка на оплату в МП); при неуспехе — ответ с незаполненными параметрами (не ошибка; бот ведёт сценарную заглушку).
- Расчёт сегмента по настраиваемым правилам при верификации + страница управления сегментами в UI (перенос из РФ «как есть»).
- Приём обещания оплаты на 1–7 дней: исключение клиента из колл-листов Genesys и рассылок на срок обещания, авто-возврат в каналы после истечения; обещание хранится в АРМ Коллектор и сохраняет силу при недоступности CraftTalk.
- Регистрация факта контакта: фиксируется только «эффективный диалог» (клиент совершил действие); обновляет «последний успешный контакт» и приоритет в колл-листах как успешный звонок.
- Вкладка «Чаты» в UI (read-only для бизнес-представителей, перенос из РФ) + результаты бота в существующей карточке/истории заёмщика без новых экранов.
- Тогл аварийного отключения чата: при включении методы агентов отвечают «сервис недоступен»; управление дежурными/ОПС без релиза, обратимо.
- **BREAKING** — нет: действующее REST API v1.1 не изменяется; новые методы — отдельной версией/спецификацией.

Вне объёма (этапы 2–3): операторы чата и операторская фиксация результатов, push-уведомления (CraftTalk→CFS→Messaging), `send_file` (досудебная претензия), плашки/статусы чата в UI, кастомная аналитика (используется ClickHouse/Metabase платформы «из коробки»).

## Capabilities

### New Capabilities

- `crafttalk-agent-api` — поперечная рамка API агентов CraftTalk: авторизация бота-пользователя, идемпотентность методов, стандартные коды ошибок, аварийный тогл отключения чата.
- `crafttalk-verification` — waterfall-верификация клиента чата (ПИНФЛ+телефон → телефон → телефон+год рождения) и выдача RAW-массива с действующими займами, сегментом и ссылкой на оплату.
- `collector-segments` — настраиваемые правила сегментации по параметрам займа/просрочки, расчёт сегмента при верификации и страница управления правилами в UI.
- `payment-promise` — приём обещания оплаты на 1–7 дней, исключение клиента из обзвона и рассылок на срок обещания и автоматический возврат в каналы.
- `contact-registration` — фиксация эффективного диалога как успешного контакта с обновлением последнего касания и приоритета обзвона.
- `chat-results-view` — отображение результатов чата: вкладка «Чаты» для бизнес-представителей и результаты бота в карточке/истории заёмщика.

### Modified Capabilities

- (нет — спецификаций проекта ещё не существует)

## Impact

- **Бэкенд**: `uzb-loans-debt-data-collection-service` (UZB-LDDCS) — новая группа `/api/craftalk/...`, роль бота, модель данных (правила сегментов, обещание оплаты, факт контакта), фоновая задача возврата в каналы, интеграция с механизмами исключения из колл-листов Genesys и рассылок.
- **UI ARM-collection**: страница сегментов, вкладка «Чаты», данные в карточке заёмщика.
- **Внешние зависимости**: контракты JS-агентов от вендора CraftTalk (блокер детализации), платёжный диплинк МП для ссылки на оплату, учётные данные бота (DevOps/безопасность).
- **Не затрагивается**: REST API v1.1 (обратная совместимость), CraftTalk/CFS/Messaging (развёртывание и настройка — DevOps), сценарии бота (продуктовая группа, вне этого изменения).
